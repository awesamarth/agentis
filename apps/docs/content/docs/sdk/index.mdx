title: SDK
description: A thin client for the Agentis API
---

Install SDK 0.5.0 or later for Agentcard support:

```sh
bun add @agentis-hq/sdk@latest
```

```ts
import { AgentisClient } from '@agentis-hq/sdk'

const client = new AgentisClient({
  baseUrl: 'https://api.agentis.systems',
  token: process.env.AGENTIS_TOKEN!,
})

const operation = await client.fetch({
  walletId: process.env.AGENTIS_WALLET_ID!,
  url: 'https://seller.example/paid-data',
  maxAmountAtomic: '10000',
}, { idempotencyKey: 'research-task-1' })
```

The SDK wraps hosted wallets, balances, policy/history reads, operations, paid fetch, grants, consent flows, Uniswap and ENS. Pending approval is a normal result with an approval URL. `operations.wait()` returns on approval-required, unknown or terminal states and never approves or resends.

Public discovery is available through `client.discovery.search({ query: 'web search', limit: 3 })` and `client.discovery.describe('exa')`. These Mercator-backed catalog reads need no token and never create a payment. Price/compatibility metadata is advisory; the actual provider challenge and normal policy remain authoritative. Discovery routes must be present on the selected backend deployment.

Use scoped executor grants in agent runtimes. Keep owner tokens out of browser bundles and unattended agents. The SDK performs no local signing or policy bypass.

## Card purchases

First complete [Agentcard setup](/docs/agentis/agentcard). Enable the plugin for the agent and grant the runtime's key separate card permission. Crypto consent alone is insufficient. Browser/Purchase flows are a preview and have not yet been verified end to end through Agentis.

```ts
const agentId = process.env.AGENTIS_AGENT_ID!
const setup = await client.cards.status(agentId)
const turn = await client.cards.purchases.ask({
  agentId,
  ask: 'Find a notebook under $10. Do not purchase yet.',
}, { idempotencyKey: 'notebook-cart-001' })
```

Inspect `turn.carts` and the intended cart's full ceiling. Confirm only the exact cart hash selected for purchase; this can place a real order immediately in Auto mode:

```ts
const checkout = await client.cards.purchases.confirm({
  agentId,
  conversationId: turn.id,
  cartHash: selectedCart.hash,
}, { idempotencyKey: 'notebook-purchase-001' })
```

`selectedCart` above is the cart you reviewed from the returned structured data. Ask mode returns `pending_approval` and a dashboard `approvalUrl`. Only the owner can approve. `client.cards.checkouts.execute(checkout.id)` can submit an already-authorized request; it cannot approve one. The dashboard's purchase approval action also submits the authorized purchase.

Read the original request with `client.cards.checkouts.get(checkout.id)`. Read an existing shopping turn with `client.cards.purchases.conversation(turn.id)`. Use `client.cards.purchases.continue(checkout.id)` only after completing a known unpaid Agentcard approval pause. Never use it as a timeout retry. Cancellation uses `client.cards.checkouts.cancel(checkout.id)`; it is not an order cancellation or refund.

## Browser checkout

Install Playwright separately and use a Chromium browser. The helper creates a context with service workers blocked and attaches the official Agentcard SDK through Agentis:

```ts
import { chromium } from 'playwright'
import { createCardCheckoutContext } from '@agentis-hq/sdk/cards/browser'

const browser = await chromium.launch({ headless: false })
const { context, page, controller } = await createCardCheckoutContext(browser, {
  client,
  agentId,
  merchant: 'Selected merchant',
  amountMinor: 1000, // USD cents: $10, not a crypto atomic amount
  idempotencyKey: 'browser-purchase-001',
  onApprovalUrl: url => { /* Present privately to the owner; do not log. */ },
})
await page.goto('https://merchant.example/checkout')
// Drive this merchant's checkout with your browser automation.
// Keep this context alive until approval and merchant completion are resolved.
// Then close context/browser. Do not recreate the purchase after uncertainty.
```

For an existing page, use `attachCardCheckout(page, options)` on a context created with `serviceWorkers: 'block'`. The exported `cardCheckoutPlaceholder` contains dummy form values for the supported interceptor flow, never the owner's real card details. The adapter handles interception, not shopping, and does not guarantee support for every merchant/processor. Do not log captures, private approval URLs or replay credentials. Keep Agentcard organization credentials on the backend.

A confirmed payment is not proof of merchant order completion. Verify the order separately. Prepared/native-checkout and future-spend APIs are not exposed by this adapter.
